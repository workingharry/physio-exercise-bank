# PhysioBank v2.0 臨床處方百科全書升級總結報告

> **專案版本**：PhysioBank v2.0  
> **升級分支**：`feat/condition-search-v2`  
> **核心目標**：讓物理治療師遇到不同病症時，無需逐個網站或影片尋找，**30 秒內**直達特定病症、特定分期的運動處方；並保留依解剖部位檢索模式。
> **交付檔案**：
> 1. 單一離線可執行 HTML 檔案：`physio_bank_standalone.html`（2.31 MB，100% 離線可用，支援 `file://` 直接雙擊開啟）
> 2. 原始專案完整源碼與類型定義（React 19 + TypeScript + Vite + TailwindCSS）
> 3. 臨床審閱與架構決策紀錄：
>    - `docs/DECISIONS.md`：ADR-001 至 ADR-007
>    - `docs/phase_repair_report.md`：分期完整度考證與修復報告
>    - `docs/chinese_name_drafts.csv`：149 筆待審核中文名稱匯總草案

---

## 1. 做了什麼 (5 行內)
1. 整合 98 個單一臨床病症與 373 個去重運動處方，建立多對多臨床適用性與分期關聯。
2. 重構首頁為雙模架構（預設病症搜尋模式 + 部位瀏覽模式），支援口語詞、繁簡錯字與別名秒搜。
3. 實作病症分期處方頁與運動百科條目頁，明確標註核心、文中提及、共用與待審核證據等級。
4. 依據 `NAVIGATION_PLAN_v2.md` 規格全面收斂側邊欄與路由：URL 為唯一真相來源，部位晶片動態計算，零死角可達性。
5. 全面套用 Anthropic/Claude 暖米色與石材灰高對比設計，產出完全自包含、零外部 API 依賴之單一離線 HTML。

## 3. 仍需人工臨床確認的清單 (Clinical Review Required)

以下項目源於文獻原文模糊性或跨病症共用特性，系統已依保守原則呈現，仍待治療師臨床審閱確認：

1. **`review_exercise_condition.csv` 中的 `mentioned`／`group` 標註**：
   - 約有部分關鍵字比對標註為「文中提及（非專屬）」，需治療師確認是否升格為「核心專屬處方」。
2. **通用踝足庫的 `suggestedConditions`**：
   - 13 個通用基礎踝足動作目前列為「建議・待臨床確認」，需確認各病症個別適用性。
3. **4 個 `nameInferred` 病症名稱**：
   - 包含原文件中缺少明確標題而依內容推論之病症，需臨床定名。
4. **中文名草稿 (`docs/chinese_name_drafts.csv`)**：
   - 149 筆原本為英文佔位之運動，已遵照指示暫以英文為主標題，並產出草案供審查。
5. **禁忌症 (Contraindications)**：
   - 原文獻未具備結構化禁忌症清單者，目前顯示全站臨床免責聲明與常規保護原則。
6. **分期仍不完整的 9 種病症**：
   - 包含脛後肌腱功能不全 (PTTD)、三角韌帶損傷、外側副韌帶損傷等，文獻原文僅記錄特定分期。
7. **共用影片連結**：
   - 98 個 YouTube 影片連結存在跨動作共用，待專項示範影片錄製後替換。

## 4. 已知限制與下一步建議

1. **上肢運動庫擴充**：
   - 目前資料結構（`types/exercise.ts`）與選擇器（`selectors.ts`）已抽離下肢專屬寫法，具備直接擴充肩、肘、腕關節能力。
2. **「目的 (Purpose)」篩選欄位**：
   - 待臨床治療師統整運動目的標準詞彙表後，可一鍵加入 URL 與右側篩選面板。
3. **病症專屬覆蓋 (Condition Context)**：
   - 可持續在 `exercises.v2.json` 的 `conditionContext` 擴充不同病症下的起始擺位與代償紅旗。

## 5. 如何重新建置與部署

```bash
# 1. 本地開發伺服器
npm run dev

# 2. 執行自動化測試門禁
node scripts/test_navigation_plan.mjs && node scripts/test_stage_a.mjs

# 3. 生成可離線直接雙擊開啟之單一 HTML 檔案
npm run build
```
建置輸出將自動儲存於根目錄之 `physio_bank_standalone.html`（檔案大小約 2.31 MB）。
